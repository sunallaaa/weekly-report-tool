# 구글 토큰 발급 가이드 (설치 없이 브라우저만으로, 약 15분)

대시보드 서버가 **팀장님 구글 계정으로** 하는 일은 세 가지입니다.

| 하는 일 | 필요한 권한 |
|---|---|
| 완성된 리포트·로우 파일을 드라이브 폴더에 저장 | Google Drive |
| 로그인 인증코드 메일 발송 (팀장님 메일 주소로 발송됨) | Gmail 발송 |
| '월예산' 시트 읽기 | Google Sheets 읽기 |

이 권한을 서버에 주는 열쇠가 **refresh token**(갱신 토큰)입니다. 한 번 발급하면 계속 쓸 수 있습니다.
받는 값은 3개입니다: **클라이언트 ID**, **클라이언트 보안 비밀번호**, **refresh token**

> ⚠️ 세 값 모두 비밀번호처럼 다뤄 주세요. 메신저·메일·깃에 올리지 말고 서버 `.env` 파일에만 넣습니다.
> 반드시 **회사 계정(@adef.co.kr)** 으로 진행하세요. 위클리 폴더가 이 계정 드라이브에 있습니다.

---

## 1단계. 구글 클라우드 프로젝트 준비

1. https://console.cloud.google.com 에 접속합니다. 오른쪽 위 계정이 **회사 계정**인지 확인합니다.
2. 왼쪽 위 **프로젝트 선택** 상자를 누릅니다.
   - PD 관리페이지 캘린더 연동에 쓴 프로젝트가 있으면 그것을 선택해도 됩니다.
   - 새로 만들려면 **새 프로젝트** → 이름 `naver-dashboard` → **만들기** → 만든 프로젝트를 선택합니다.

## 2단계. API 3개 켜기

1. 왼쪽 메뉴(☰) → **API 및 서비스** → **라이브러리**
2. 검색창에 아래 이름을 하나씩 검색 → 들어가서 **사용** 버튼을 누릅니다.
   - `Google Drive API`
   - `Gmail API`
   - `Google Sheets API`

## 3단계. 동의 화면 설정 (처음 한 번)

1. 왼쪽 메뉴 → **API 및 서비스** → **OAuth 동의 화면** (화면에 따라 **Google 인증 플랫폼**으로 보일 수 있음)
2. **시작하기**(또는 **구성**)를 누르고 아래처럼 입력합니다.
   - 앱 이름: `네이버 광고 대시보드`
   - 사용자 지원 이메일: 내 회사 메일
   - **대상(사용자 유형): `내부`** ← 중요
   - 연락처 이메일: 내 회사 메일
3. **만들기**를 누릅니다.

> **왜 '내부'인가요?** 회사 계정만 쓰는 앱이라 구글 심사가 필요 없고, 토큰이 만료되지 않습니다.
> '외부' + '테스트' 상태로 만들면 **7일마다 토큰이 만료**되어 서버가 멈춥니다.
> 이미 프로젝트가 '외부'로 되어 있으면 **대상** 메뉴에서 '내부'로 바꿀 수 있습니다.

## 4단계. OAuth 클라이언트 만들기

1. 왼쪽 메뉴 → **API 및 서비스** → **사용자 인증 정보** (또는 Google 인증 플랫폼 → **클라이언트**)
2. 위쪽 **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
3. 아래처럼 입력합니다.
   - 애플리케이션 유형: **웹 애플리케이션**
   - 이름: `naver-dashboard-server`
   - **승인된 리디렉션 URI** → **+ URI 추가** → 아래 주소를 **정확히** 붙여넣기
     ```
     https://developers.google.com/oauthplayground
     ```
4. **만들기**를 누르면 창이 뜹니다. **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 메모장에 복사해 둡니다.

## 5단계. refresh token 받기 (OAuth Playground)

구글이 제공하는 공식 테스트 페이지입니다. 설치할 것이 없습니다.

1. https://developers.google.com/oauthplayground 에 접속합니다.
2. 오른쪽 위 **톱니바퀴(⚙)** 를 누릅니다.
   - **Use your own OAuth credentials** 에 체크합니다.
   - **OAuth Client ID** / **OAuth Client secret** 칸에 4단계에서 복사한 값을 붙여넣습니다.
   - 같은 창의 **Access type** 은 `Offline` 그대로 둡니다.
   - **Close** 를 누릅니다.
3. 왼쪽 **Step 1** 목록 맨 아래 **Input your own scopes** 칸에 아래 한 줄을 그대로 붙여넣습니다. (띄어쓰기로 구분된 주소 3개)
   ```
   https://www.googleapis.com/auth/drive https://www.googleapis.com/auth/gmail.send https://www.googleapis.com/auth/spreadsheets.readonly
   ```
4. 파란 **Authorize APIs** 버튼을 누릅니다.
   - 회사 계정을 선택하고, 권한 3개를 **허용**합니다.
5. 화면이 **Step 2** 로 넘어가면 **Exchange authorization code for tokens** 버튼을 누릅니다.
6. **Refresh token** 칸에 `1//0` 으로 시작하는 긴 값이 나옵니다. 이 값을 복사합니다.
   - Access token(`ya29.`로 시작)은 1시간짜리라 필요 없습니다.

## 6단계. 서버 `.env` 에 넣기

`/home/seonhwa_choi/naver-dashboard/.env` 에 세 줄을 채웁니다.
```
GOOGLE_CLIENT_ID=4단계의 클라이언트 ID
GOOGLE_CLIENT_SECRET=4단계의 클라이언트 보안 비밀번호
GOOGLE_REFRESH_TOKEN=5단계의 Refresh token
```
저장한 뒤 서버에서 `docker compose up -d naver-dashboard` 를 실행합니다.

**확인:** 대시보드 **관리** 화면의 연결 상태에 🟢 구글이 보이고, **월예산 확인 → 불러오기**에 11월 예산이 나오면 성공입니다.

## 이럴 땐 이렇게

| 화면/문구 | 원인 → 해결 |
|---|---|
| `redirect_uri_mismatch` | 4단계 리디렉션 URI가 정확하지 않음 → `https://developers.google.com/oauthplayground` (끝에 `/` 없이) 다시 입력 |
| `액세스 차단됨` / `앱이 확인되지 않음` | 동의 화면이 '외부'로 되어 있음 → 3단계 '내부'로 변경 |
| Refresh token 칸이 비어 있음 | 톱니바퀴 → Access type `Offline` 확인 → Step 1부터 다시 |
| `내부` 선택지가 없음 | 개인 Gmail 계정으로 들어간 경우 → 오른쪽 위에서 회사 계정으로 전환 |
| 회사 정책상 API 사용이 막힘 | 이 경우만 구글 워크스페이스 관리자(IT)에게 문의 |

**토큰이 유출됐을 때:** https://myaccount.google.com/permissions → `네이버 광고 대시보드` → **액세스 권한 삭제** → 5단계를 다시 진행합니다.
